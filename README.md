# Benua · Telegram Bot Template

Основа Telegram-бота на Python и aiogram 3 для развития в прикладной продукт: приём заявок, диалоги, интеграции с сервисами и ИИ-помощники.

Проект связан с направлением [Benua — ИИ и разработка цифровых продуктов](https://thebenua.online/): соединять логику, данные и интерфейс вокруг понятного действия пользователя. Здесь интерфейсом служит Telegram.

Это стартовый каркас. Сейчас бот отвечает на `/start`; остальные сценарии добавляются под конкретную задачу.

## Что уже есть

| Компонент | Состояние в репозитории |
| --- | --- |
| Запуск бота | Асинхронный polling через `Dispatcher` |
| Обработка команд | Отдельный роутер с `/start` |
| Конфигурация | `pydantic-settings`, чтение `.env`, токен как `SecretStr` |
| Логи | Стандартный `logging` на уровне INFO |
| PostgreSQL и Redis | Зависимости и сервисы Compose; подключения из Python ещё нет |
| Docker | Заготовка Compose; Dockerfile пока отсутствует |
| ИИ и внешние API | Точки развития; готовых интеграций пока нет |

Нагрузочные тесты, CI и готовность к production этим репозиторием пока не подтверждены.

## Для каких задач развивать шаблон

- **Заявки:** собрать запрос, уточнить детали, показать подтверждение и передать данные ответственному.
- **Диалоги:** провести человека через несколько шагов с возможностью вернуться назад или отменить действие.
- **Сервисные действия:** получить статус заказа, запросить данные из API или отправить уведомление.
- **ИИ-помощник:** принять вопрос, собрать нужный контекст и вернуть ответ в рамках заданной роли.

Это примеры будущих сценариев, а не перечень уже реализованных функций. Для первой версии стоит выбрать один путь от команды до полезного результата.

## Технологии

| Технология | Версия в requirements.txt | Назначение |
| --- | --- | --- |
| aiogram | 3.13.1 | Telegram Bot API, маршрутизация событий |
| pydantic-settings | 2.4.0 | Настройки из окружения и `.env` |
| SQLAlchemy | 2.0.32 | Зависимость для будущего слоя данных |
| asyncpg | 0.29.0 | Асинхронный драйвер PostgreSQL |
| redis | 5.0.8 | Клиент для будущего хранилища состояний |
| loguru | 0.7.2 | Установлен; текущий код использует стандартный `logging` |

Для воспроизводимого старта используйте Python 3.11 и отдельное виртуальное окружение. Обновление закреплённых версий требует отдельной проверки совместимости.

## Структура репозитория

```text
aiogram3-bot-template/
├── config/
│   └── config.py        # Settings и загрузка окружения
├── handlers/
│   └── common.py        # Router и команда /start
├── main.py             # Bot, Dispatcher, logging, polling
├── requirements.txt    # Закреплённые зависимости
├── docker-compose.yml  # Заготовка bot + PostgreSQL + Redis
└── README.md
```

Файл `.env` создаётся локально. Каталогов сервисов, моделей БД и миграций в текущем каркасе ещё нет.

## Как проходит запрос

```text
Telegram → polling → Dispatcher → common.router → cmd_start → ответ
```

При запуске импортируется `settings`, проверяются обязательные переменные, создаются `Bot` и `Dispatcher`, подключается роутер. Затем `start_polling` получает события Telegram.

При расширении обработчик должен отвечать за входные данные и сообщение пользователю. Правила продукта и обращения к внешним системам удобно выносить в отдельные сервисы, чтобы их можно было проверять без Telegram.

## Перед запуском

Понадобятся Git, Python 3.11 с `pip`, доступ к Telegram API и токен бота, созданного через [BotFather](https://t.me/BotFather).

Запускайте команды из корня проекта: `.env` читается относительно текущего рабочего каталога. Для проверки существующей команды `/start` работающие PostgreSQL и Redis не нужны, но строки их подключения обязательны для модели настроек.

Токен даёт доступ к управлению ботом. Не вставляйте его в исходный код, сообщения об ошибках или публичные примеры.
